# 상태 파일과 장부 · 두 트랙이 어떻게 굴러가나

## 1. 폴더 모양

```
내위키/
├── CLAUDE.md
├── .inbox/                     ← 야간수집.cmd · collect.log · 걸러낼도메인.txt
├── raw/
│   ├── _수집상태.json          ← 두 트랙의 상태. _ 로 시작해서 장부에 안 잡혀요
│   ├── 카톡/
│   │   └── 2026-09/
│   │       └── 현장 단톡방_5678.md   ← 뒤 네 자리는 방 번호예요
│   └── 메일/
│       ├── 2026-09/
│       │   └── 2026-09-14_a3f1b2c8_견적서 회신.md
│       └── _걸러짐/            ← 광고·알림. 버리지 않고 여기 둬요
│           └── 2026-09/
└── wiki/
    ├── index.md · log.md · tags.md · 장부.md
    └── (페이지들)
```

**새로 생기는 규칙은 하나예요** · `raw/` 안에서 **이름이 `_` 로 시작하는 파일과 폴더는 자료가 아니에요.** 장부에도 안 올라가고 점검에서도 안 세요.

## 2. `raw/_수집상태.json`

```json
{
  "format": 2,
  "wiki_root": "C:/Users/나/Documents/내위키",
  "updated_at": "2026-09-19T23:04:11+09:00",
  "realtime_files": ["카톡/2026-09/현장 단톡방_5678.md"],
  "mail_filter_domains": ["shop.example.com"],
  "sources": {
    "메일:me@example.com": {
      "kind": "mail", "mode": "imap",
      "host": "imap.naver.com", "port": 993, "user": "me@example.com",
      "secret_label": "mail:me@example.com", "deterministic": true,
      "first_run_done": false,
      "backfill_start": "2026-04", "backfill_cursor": "2026-07", "backlog_remaining": 3,
      "last_epoch": 1758283861, "last_run": "2026-09-19T23:04:11+09:00",
      "collected": 214, "filtered": 96, "last_error": null
    },
    "카톡:현장 단톡방": {
      "kind": "kakao",
      "skill_dir": "C:/Users/나/.claude/skills/kakao-windows", "kakao_state_dir": null,
      "room": "현장 단톡방", "room_id": "12345678", "account": null, "deterministic": true,
      "first_run_done": true,
      "backfill_start": "2026-03", "backfill_cursor": null, "backlog_remaining": 0,
      "last_epoch": 1758283100, "last_run": "2026-09-19T23:04:09+09:00",
      "months": ["2026-03", "2026-09"], "collected": 1884, "last_error": null
    }
  }
}
```

| 칸 | 뜻 |
|---|---|
| `last_epoch` | 이 소스에서 마지막으로 본 메시지·메일의 시각(초). 다음 실시간 수집의 시작점이에요 |
| `last_run` | 스크립트가 마지막으로 돈 시각. 실패해도 갱신돼요(`last_error` 와 짝이에요) |
| `first_run_done` | 예전 것을 다 받았나요. `false` 면 아직 과거 트랙이 돌고 있어요 |
| `backfill_start` · `backfill_cursor` | 과거 트랙이 어디까지 왔나요. 커서는 **다음에 시작할 달**이에요. 커서가 이번 달을 지나면 `first_run_done: true`, 커서는 `null` |
| `backlog_remaining` | **남은 달 수**예요. 장부의 남은 건수와는 다른 숫자예요 |
| `realtime_files` | **실시간 트랙이 가져온 파일**(최대 200개). "새로 온 것"을 여기서 세요. 과거 트랙이 받은 파일은 여기 안 들어가요. 장부에 올라가기 전까지는 다음 회차에도 남아 있어요 |
| `room_id` · `account` | 카톡 방 번호(chat_id)와 계정. 방 이름이 바뀌어도 번호로 계속 잡혀요 |
| `secret_label` | 보관함의 이름표. **비밀번호 값은 이 파일에 절대 안 들어가요** |

`mail_filter_domains` 는 걸러낼 발신자 도메인이에요. **`<위키폴더>/.inbox/걸러낼도메인.txt`** 에 한 줄씩 적으면 수집할 때마다 읽어서 여기에 합쳐요. 그 파일이 없으면 `templates/걸러낼도메인.txt` 를 거기로 복사해서 쓰세요. 한 번 합쳐진 도메인은 txt 에서 지워도 상태 파일에 남아요.

## 3. 두 트랙

### 새로 오는 것 (실시간)

- 시작점은 `last_epoch` 에서 **한 시간을 뺀 시각**이에요. 처음이면 어제부터요.
- 겹침 때문에 같은 메일·메시지를 다시 받지만 결과는 안 바뀌어요. 메일은 파일 이름이 같아서 건너뛰고, 카톡은 그 달을 통째로 다시 쓰니까요.
- 메일 검색은 **날짜 단위**라 시간까지 자르지 못해요. 그래서 하루치를 다시 보고 이미 있는 파일은 건너뛰어요. 정상이에요.
- 끝나면 `last_epoch` 을 이번에 본 것 중 가장 늦은 시각으로 올려요.

### 밀린 것 (과거)

1. 처음 연결할 때 고른 범위를 `backfill_start` 에 적어요.
2. **달 단위로 오래된 것부터** 내려받아요. 한 회차에 카톡은 월 파일 30개, 메일은 3개월치까지요. 끝낸 다음에 커서는 **그다음 달**로 올라가요. 그래서 6개월이면 두 회차예요.
3. 받은 파일은 창고에 그냥 쌓여요. **장부에는 아무것도 안 적어요.** 장부에 올리는 건 `llm-wiki-factory` 의 "넣어줘"가 해요.
4. 회차마다 **20건**만 판정돼요. 그래서 1년치를 받아도 하루에 폭발하지 않아요.
5. 커서가 이번 달을 지나면 `first_run_done: true` 가 돼요.
6. 여기서 받은 파일은 `realtime_files` 에 **안 들어가요.** 받자마자 "밀린 것"이에요.

## 4. 몇 번을 돌려도 같은 이유

- **카톡** · 달을 통째로 다시 써요. 창이 항상 달의 첫날부터라 덮어써도 잃는 게 없어요.
- **메일** · 파일 이름에 메일 고유 번호가 들어 있어서 같은 메일은 같은 이름이 되고, 이미 있으면 건너뛰어요.
- **두 트랙이 같은 달을 같이 건드려도** 결과는 하나예요.
- **중간에 멈춰도** 상태 파일은 회차 끝에서 한 번만 고쳐 써요. 다시 돌리면 멈춘 달부터 다시 해요.
- 파일을 손으로 지우면 **실시간 창 안에 있는 것만** 다시 만들어져요. 오래된 달을 다시 받으려면 그 달을 커서로 되돌려야 해요.
- **같은 등록 명령을 한 번 더 쳐도 진행 상태가 안 날아가요.** 접속 정보만 갱신하고 커서와 `last_epoch` 은 그대로 둬요.

## 5. 장부와 어떻게 맞물리나

- 장부의 **「원본 파일」 칸에는 `raw/` 부터의 상대 경로**를 적어요. 예 · `카톡/2026-09/현장 단톡방_5678.md`
  파일 이름만 적으면 다른 달의 같은 방 파일과 구분이 안 돼요.
- `llm-wiki-factory` 가 창고를 훑을 때 **하위 폴더까지 전부** 보고, `_` 로 시작하는 것은 빼요.
- 한글 이름은 양쪽 다 같은 형태(NFC)로 맞춰서 비교해요.

**보고 문장 틀**

> 정리했어요 · 올림 12 · 버림 6 · 보류 2
> **새로 온 것 3건**은 다 처리했고, **밀린 것은 140건 중 17건**을 했어요. 남은 123건은 "밀린 거 처리해줘"라고 하실 때마다 스무 건씩 할게요.

- 고르는 순서는 `llm-wiki-factory` 3절 2항이 정본이에요. **새로 온 것으로 20칸을 먼저 채우고 남는 자리를 밀린 것으로** 채워요.
- 새로 온 것이 20건을 넘으면 밀린 것은 그 회차에 건너뛰고 그렇게 말씀드려요.

## 6. 숫자 세기

```
python "<스킬폴더>/scripts/inbox_status.py" --wiki "C:/Users/나/Documents/내위키"
```

| 나오는 숫자 | 뜻 |
|---|---|
| `raw_files` | 창고 파일 수(`_` 로 시작하는 것 빼고) |
| `ledger_rows` | 장부에 적힌 줄 수 |
| `ledger_found` | 장부 파일을 찾았는지. `false` 면 아래 숫자를 믿으면 안 돼요 |
| `unprocessed` | 장부에 아직 없는 창고 파일 수 = **아직 안 들어간 것** |
| `realtime_new` | 그중 실시간 트랙이 가져온 것 = **새로 온 것** |
| `backlog` | 그 나머지 = **밀린 것** |

`--list` 를 붙이면 파일 이름까지 보여 줘요. **이 숫자를 제가 어림하지 않아요.**
