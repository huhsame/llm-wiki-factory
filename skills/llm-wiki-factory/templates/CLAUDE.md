# {내 위키}

{무슨 자료를 모으는 위키인지 한 줄}

목차 `wiki/index.md` · 기록 `wiki/log.md` · 서랍 `wiki/tags.md` · 장부 `wiki/장부.md`
현황: 페이지 0장 · 자료 0건 · 마지막 정리 {2026-09-19}

## 내 일 소개

(아직 안 적었어요. "둘러봐줘"라고 하시면 메일과 카톡의 겉을 훑어서 채워 드려요. 1분이면 돼요.)

> 판정하고 페이지를 쓸 때 이 문단을 배경으로 봐요. 여섯 줄을 넘기지 않고, 연락처는 안 적어요.

## 이 폴더의 약속 네 가지

1. **`raw/`는 절대 안 고쳐요.** 이름도 내용도 그대로 둬요.
2. **입구는 둘, 문은 하나.** 예전 자료든 새 자료든 판정도 페이지 형식도 똑같아요.
3. **버린 것도 기록에 남겨요.** 위키에 안 올린 자료도 장부에 한 줄 남아요.
4. **소스에 없는 말은 안 적어요.** 안 나온 건 `(확인 안 됨)`으로 남겨요.

**위키는 AI가 써요. 저는 자료를 넣고, 물어보고, 맞는지 확인해요.**

## 질문을 받으면

1. 먼저 `wiki/index.md`를 읽어요. 목차에서 관련 페이지를 골라요.
2. 고른 페이지를 읽고, 여러 장이면 합쳐서 답해요.
3. **답에 출처를 `[[페이지이름]]`으로 붙여요.** 출처 없는 문장은 쓰지 않아요.
4. 위키에 없으면 "위키에 없어요"라고 먼저 말하고 `raw/`를 찾아봐요.
   원본에 있으면 "원본에는 있는데 아직 위키에 안 올렸어요"라고 알려요.
   그래도 없으면 어디를 찾아봤는지 목록으로 보여줘요. **지어내지 않아요.**
5. 답이 길거나 여러 페이지를 합친 거면 한 번 물어봐요.
   "이 답을 페이지로 저장할까요?" 예라고 하면 `wiki/`에 저장해요.
   이 페이지도 아래 「페이지 형식」대로 맨 위를 채우고 `type: 기록`으로 적어요.
   `## 출처`에는 답에 쓴 페이지 이름을 넣어요.
   그다음 목차 「물어본 답」에 한 줄, `wiki/log.md`에 한 줄 추가해요.

## 자료를 넣으라고 하면

1. `wiki/장부.md`에 `보류`가 있으면 **먼저 한꺼번에 물어봐요.**
   `wiki/_둘러보기.md` 쪽지가 있으면 **여기서 먼저 읽어요.** 이름 표기를 맞추고, 「업무 아님」으로
   표시된 곳을 가리는 데 써요. **쪽지만으로는 페이지를 만들지 않아요.**
2. `raw/`에서 장부에 없는 파일만 골라요. 한 번에 20건까지요.
   **하위 폴더까지 전부 훑되, 이름이 `_`로 시작하는 파일과 폴더는 빼요**(`_수집상태.json`·`_걸러짐/`).
   `raw/_수집상태.json`이 있으면 **새로 온 것으로 잡힌 파일부터 20칸을 채우고 남는 자리를 밀린 것으로** 채워요.
   같은 묶음 안에서는 폴더 이름 순, 그 안에서 파일 이름 순이에요.
   **장부의 원본 파일 칸에는 `raw/`부터의 상대 경로를 적어요**(예 · `메일/2026-09/2026-09-14_a3f1b2c8_견적서 회신.md`).
   이름이 비슷한 파일(같은 문서의 다른 버전)은 한 회차에 같이 넣어요.
   이름 끝에 `(1)`·`사본`이 붙었거나 장부에 있는 파일과 크기가 같으면, `대기`로 적기 전에 열어서 같은 자료인지부터 봐요.
   같으면 "이건 N월 N일에 넣었어요"라고 말하고, 페이지는 다시 쓰지 않고 장부에 `버림` 한 줄만 남겨요.
3. **고른 파일 전부를 장부에 `대기`로 먼저 적어요.** 판정 전에 적어요.
4. 판정하고(아래), `올림`이면 페이지를 쓰거나 기존 페이지에 붙여요.
   붙일 때는 `## 내용`을 날짜 순으로 다시 세우고, 이미 적힌 사실과 겹치면 한 줄로 합쳐요.
5. `wiki/index.md` · `wiki/tags.md` · `wiki/장부.md` · `wiki/log.md`를 같이 고쳐요.
6. 올림 N · 버림 N · 보류 N과 새 페이지 이름을 알려줘요.
   끝내기 전에 장부에 `대기`가 남았는지, 장부 행 수가 `raw/` 파일 수(`_`로 시작하는 것 빼고)와 같은지 봐요.

**올림·버림은 묻지 않고 정해요. 보류만 모아서 한 번에 보여줘요.**

**원본이 안 읽히면**: 먼저 파일 읽기 도구로 열어 보고 **한글이 제대로 보이면** 그걸로 끝이에요. 안 되면 파이썬 기본 기능으로 풀어요. Word와 PPT는 속이 zip이라 `zipfile`로 안쪽 XML에서 글자만 긁어내고, 메일(`.eml`)은 `email` 모듈로 풀어요. 엑셀은 `openpyxl`이 있으면 그걸 쓰고 없으면 같은 방식으로요. **뭘 설치하지 않아요.** 뽑은 글자는 **위키 페이지에 요약으로만** 반영하고 `raw/` 옆에 변환 파일을 만들지 않아요. 그래도 못 읽으면 「다른 이름으로 저장」으로 텍스트나 PDF를 달라고 한 줄 부탁하고, 그동안은 `보류`로 둬요.

## 판정

| 판정 | 이럴 때 |
|---|---|
| 올림 | 다시 찾아볼 사실이 있어요(결정·금액·날짜·담당·조건) / 200자 넘는 한 주제 / 기존 페이지에 붙일 내용 |
| 버림 | 자동 알림·영수증·광고 / 같은 내용의 중복 파일 / 내용이 거의 없음 / 둘러보기에서 「업무 아님」으로 표시한 곳에서 온 것 |
| 보류 | 누군지 저만 알아요 / 개인적인 내용이라 제가 정해야 해요 / 무슨 문서인지 모르겠어요 |

- 사람·회사·프로젝트 이름이 **서로 다른 파일 2건 이상**에 나오면 **묻지 말고 페이지를 만들어요.** 1건이면 그 자료 페이지에 한 줄만요.
- 중복 파일은 **대표 하나만** 올리고, 버린 쪽 이유에 대표 파일 이름과 같다고 본 근거를 적어요.
- 이름이 안 닮아도 중복일 수 있어요. 크기가 같은 파일이 둘 있으면 열어서 내용을 견줘 봐요.
- 한 파일에 별개 회의가 이어지면 나눠서 각각 판정해요.
- 말투가 안부성이어도 **일 때문에 알게 된 사람**이면 업무예요.
- 버린 것에는 **이유를 꼭** 적어요. 둘러보기 표시 때문에 버렸으면 그 표시를 이유에 그대로 옮겨 적어요.

## 페이지 형식

맨 위 (기계가 읽어요):
`type` · `tags`(분야/ 종류/ 활동/ 세 개 필수) · `created` · `started` · `ended` · (선택) `aliases` · `checked`
`type` 값은 `사람`·`조직`·`프로젝트`·`회의`·`개념`·`기록` 여섯 중 하나고, `wiki/tags.md`의 `종류/` 서랍과 이름이 똑같아요.
`ended`와 `checked`는 비워 두고, 일이 끝났을 때·원문과 대조했을 때만 날짜를 넣어요.
`status`는 쓰지 않아요. 처리 상태는 장부에만 둬요.

본문: `## 요약`(두세 문장) → `## 내용`(날짜별 사실) → `## 관련 페이지` → `## 출처`(원본 파일 경로)

- 메일·문서를 통째로 붙이지 않아요. **결정·일정·금액**만요. 금액은 원문 그대로요.
- **`## 출처`는 모든 페이지에 필수예요.** 원본의 `raw/` 경로를 적어요. 비어 있으면 미완성이에요.
- **연락처는 안 적어요.** 전화번호·개인 메일은 빼고 원본 경로만 남겨요. 이름·소속·직함·정해진 사실은 그대로 둬요. 회사 도메인 업무 메일은 남겨도 돼요.
- 누가 말했는지 확실하지 않으면 "대화에서 이런 말이 나왔다"로 적어요.

## 목차·서랍·기록

- **모든 페이지가 `wiki/index.md`에 한 줄이에요. 예외 없어요.** 다만 `_둘러보기.md`처럼 **이름이 `_`로 시작하는 파일은 페이지가 아니라 쪽지**라서 목차에도 점검에도 안 넣어요. 한 페이지는 한 줄이고, 형식은 대괄호 두 개로 감싼 페이지 이름 뒤에 쌍점을 찍고 한 줄 설명이에요.
- 서랍은 미리 만들어 둔 것 중에서 골라요. 새로 만들기 전에 "기존 걸로 안 되나?"를 먼저 봐요. 서랍이 40개를 넘으면 합칠 게 있는지 물어봐요.
- `wiki/log.md`는 제목이 **날짜만**이에요(`## 2026-09-19`). 무엇을 했는지는 항목 앞 굵은 글씨로요. 새 회차가 맨 위로 가요.
- 같은 날 또 하면 새 덩어리를 만들지 말고 **그날 덩어리 안에 항목만 더해요.** 제목은 하루에 하나예요.
- **판단이 갈린 지점과 왜 그렇게 정했는지**를 기록에 한 줄 남겨요.

## 안 하는 것

- `raw/` 파일을 고치거나 이름을 바꾸지 않아요.
- 비밀번호·API 키를 파일이나 위키에 적지 않아요.
- 한 번에 20건 넘게 처리하지 않아요.
- 위키 파일을 PowerShell의 `>`·`Out-File`·`Set-Content`로 저장하지 않아요. 파일 쓰기 도구로 직접 써요.
- 페이지 이름에 `\ / : * ? " < > |` 아홉 글자를 쓰지 않아요. Windows가 저장을 거부해요. `A/B 테스트 결과는?` 같은 제목은 `A-B 테스트 결과`로 바꿔 저장하고 원래 제목은 본문 첫 줄에 적어요.
