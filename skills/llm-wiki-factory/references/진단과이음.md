# 진단과 이음 · 이미 만든 위키를 갈아엎지 않고 잇기

SKILL.md 2절 「0. 먼저 봐요」의 정본이에요. 수업에서 각자 만든 폴더에 이 스킬을 처음 부를 때 쓰는 길이에요.

```
진단(읽기만)  →  계획 설명  →  확인 한 번  →  비파괴 실행  →  안내 페이지  →  보고 다섯 줄
```

새로 짓는 절차(2절 1번부터)는 **흔적이 없을 때만** 돌아요. 흔적이 있으면 이 문서의 길로 가요.

---

## 1. 진입 조건

### 1.1 어떤 말에서 켜지나

`위키 만들어줘` · `세팅해줘` · `내 위키 봐줘` · `지금 어디까지 됐어` · `이 폴더 어떻게 돼 있어` · `내 위키 상태 알려줘`

이 말들은 전부 **먼저 폴더를 보고** 갈림길을 정해요. 말만 듣고 바로 만들지 않아요.

### 1.2 무엇이 있으면 진단인가

둘 중 하나면 진단 모드예요.

- `wiki/` 폴더가 있고 그 안에 `.md` 파일이 **하나 이상** 있어요
- `raw/` 폴더가 있고 그 안에 파일이 **하나 이상** 있어요

**`CLAUDE.md`는 혼자서는 신호가 아니에요.** 위 둘 중 하나와 같이 있을 때만 세요. `CLAUDE.md`만 있는 폴더는 위키가 아니라 그냥 개발 프로젝트일 때가 훨씬 많아요. 거기서 진단표를 꺼내면 엉뚱한 일이 돼요.

빈 `wiki/`와 빈 `raw/`만 있으면 진단이 아니에요. 셀 게 없으니까 **2절 1번(새로 만들기)** 으로 그대로 가요. 이미 있는 빈 폴더는 지우지 않고 그대로 써요.

### 1.3 어디까지 찾나

1. **지금 열린 폴더**부터 봐요
2. 없으면 **한 단계 위**를 한 번 봐요. 다만 한 단계 위가 **사용자 홈 폴더**면 올라가지 않아요. 홈 폴더 밑에는 남의 폴더도 섞여 있고 파일이 수만 개일 수 있어요
3. 없으면 **바로 아래 폴더들**(한 겹만)을 봐요. 더 깊이는 안 들어가요

세 군데 어디에도 없으면 진단 모드가 아니에요. 2절 1번으로 가요.

**두 군데 이상에서 나오면** 목록으로 보여드리고 번호로 고르게 해요. 이건 확인 질문(3.4)과 별개로 세요. 추측해서 하나를 고르면 남의 폴더를 건드릴 수 있어요.

```
위키로 보이는 폴더가 둘이에요. 어느 쪽을 볼까요?

① 내위키          페이지 7장 · 창고 23건
② 실습/01_폴더정리  페이지 0장 · 창고 4건
```

### 1.4 갈림길 셋

| 찾은 것 | 어디로 | 무엇을 하나 |
|---|---|---|
| 아무 흔적 없음 | 2절 1번 | 지금까지 하던 대로 새로 만들어요 |
| 흔적 있고 `wiki/장부.md` **없음** | **진단 모드** | 이 문서 2~4절 |
| 흔적 있고 `wiki/장부.md` **있음** | **가벼운 진단** | 진단표만 보여드리고, 고칠 게 0이면 확인 질문 없이 안내 페이지만 다시 채워요 |

**「위키 점검해줘」는 언제나 SKILL.md 8절이에요.** 이 표로 오지 않아요. 다만 `wiki/장부.md`가 아예 없으면 8절을 시작하기 전에 진단표를 한 번 보여드려요. 점검은 **빠진 것과 어긋난 것을 세는 일**이고 진단은 **구조를 보는 일**이라 서로 다른 일이에요.

**「고칠 게 0」은 넷이 다 0일 때예요** · ① `없음`인 뼈대 파일 ② 맨 위 머리가 없는 페이지 ③ 목차에 빠진 페이지 ④ `CLAUDE.md`에 우리 규칙 절이 없음. **「출처 없음 N장」·「연결된 소스 없음」·「밤 자동화 없음」은 여기에 안 넣어요.** 손으로 넣는 위키는 이 셋이 늘 걸려 있어서 넣으면 영영 0이 안 되고, 두 번째 실행에서도 계획과 확인 질문이 또 떠요.

**가벼운 진단에서는 이렇게 말해요.** 매번 새로 지어내지 않아요.

```
이 폴더는 이미 잇혀 있어요. 지금 숫자만 보여 드릴게요.

(진단표 열다섯 줄)

고칠 게 없어요. 안내 페이지만 새 숫자로 다시 채웠어요.
```

### 1.5 큰 폴더 보호

- `raw/` 파일이 **2,000개**를 넘으면 세기 전에 한 줄 먼저 말해요 · "창고가 아주 커요. 세는 데 몇 분 걸릴 수 있어요."
- `wiki/` 안 `.md`가 **500장**을 넘으면 맨 위 머리·출처 비율은 **앞 500장만** 세고 표에 `500장 중`이라고 적어요. 어림하지 않아요.

## 2. 진단 항목과 진단표

### 2.1 원칙

**진단은 읽기만 해요.** 백업도 이 단계에서는 안 해요. 아무것도 안 고치니까 백업할 게 없어요. 표 맨 위에 이 한 줄을 꼭 붙여요.

> 읽기만 했어요. 아직 아무것도 안 고쳤어요.

### 2.2 「지금」 칸에 쓰는 말 다섯 가지

`있음` · `없음` · `다름` · 숫자 · `N/M`

이 다섯 개만 써요. 「부분적으로 있음」 같은 말을 만들지 않아요. 표를 훑는 사람이 세 글자 안에서 판단할 수 있어야 해요.

`다름`은 **파일은 있는데 우리 규칙과 모양이 다를 때**예요. 「틀렸다」는 뜻이 아니라 「손댈 자리가 있다」는 뜻이에요. 한 줄 설명에 무엇이 다른지 꼭 적어요.

### 2.3 진단표 · 한 표에 열다섯 줄

**아래 숫자는 보기예요. 꼭 직접 세요.** 베껴 쓰면 남의 폴더 숫자를 그 사람 화면에 띄우게 돼요.

```
읽기만 했어요. 아직 아무것도 안 고쳤어요.

| 볼 것 | 지금 | 한 줄 |
|---|---|---|
| 원본 창고 `raw/` | 있음 | 파일 23개가 들어 있어요 |
| 위키 `wiki/` | 있음 | 페이지 7장이에요 |
| 규칙 `CLAUDE.md` | 다름 | 있는데 우리 규칙 절이 없어요 |
| 목차 `wiki/index.md` | 있음 | 7장 중 6장이 올라가 있어요 |
| 기록 `wiki/log.md` | 있음 | 회차 한 덩어리가 적혀 있어요 |
| 서랍 `wiki/tags.md` | 없음 | 태그를 고를 목록이 없어요 |
| 장부 `wiki/장부.md` | 없음 | 창고 23건 중 어디까지 했는지 적힌 데가 없어요 |
| 창고 자료 | 23건 | 장부가 없어서 몇 건이 페이지가 됐는지는 아직 몰라요 |
| 페이지 | 7장 | 하위 폴더 없이 한 층이에요 |
| 목차 등재율 | 6/7 | 한 장이 목차에 안 올라가 있어요 |
| 출처가 적힌 페이지 | 0/7 | 어느 파일에서 왔는지가 페이지에 안 적혀 있어요 |
| 맨 위 머리가 있는 페이지 | 0/7 | 종류·서랍·날짜 줄이 없어요 |
| 원본이 바뀐 흔적 | 없음 | 창고에 변환본으로 보이는 파일이 없어요 |
| 연결된 소스 | 없음 | 카톡·메일은 아직이고 손으로 넣고 계세요 |
| 밤 자동화 | 없음 | 걸어 둔 게 없어요 |
```

**열다섯 줄 고정이에요.** 해당 없는 줄도 빼지 않아요. 빼면 사용자가 「이건 안 봤나?」를 되물어요.

표 아래에 한 줄 붙여요 · "여기서 제일 큰 건 **장부가 없다**는 거예요. 창고에 뭐가 들어왔고 어디까지 했는지를 아무 데도 안 적고 있어서, 다음에 자료를 넣으면 같은 걸 또 읽게 돼요."

무엇이 제일 큰 문제인지는 **아래 순서로 첫 번째 걸리는 것**을 고르면 돼요.

1. 장부 없음
2. 목차 없음 또는 등재율이 절반 아래
3. 출처가 적힌 페이지가 0
4. 규칙 파일 없음 또는 다름
5. 위 넷이 다 괜찮으면 · "잘 굴러가고 있어요"

### 2.4 각 줄을 세는 법

**빼고 세는 것(공통)**

- 이름이 `_`로 시작하는 파일과 폴더(`_수집상태.json`·`_걸러짐/`·`_둘러보기.md`)
- 뼈대 파일 넷 · `index.md`·`log.md`·`tags.md`·`장부.md`
- ` ``` `로 열고 닫는 상자 안의 줄(장부를 셀 때)
- 한글 이름은 양쪽 다 같은 형태(NFC)로 맞춰서 비교해요

이건 SKILL.md 8절의 세는 법과 **똑같아요.** 진단과 점검이 다른 방식으로 세면 숫자가 어긋나서 사용자가 둘 다 못 믿어요.

**줄별 판정 기준**

| 줄 | 있음 | 다름 | 없음 |
|---|---|---|---|
| `raw/` | 폴더가 있고 파일이 1개 이상 | 폴더는 있는데 비어 있음 | 폴더가 없음 |
| `wiki/` | 폴더가 있고 `.md`가 1장 이상 | 폴더는 있는데 비어 있음 | 폴더가 없음 |
| `CLAUDE.md` | 우리 규칙 절(4절 단계 6의 제목 줄)이 있음 | 파일은 있는데 그 절이 없음 | 파일이 없음 |
| `index.md` | 파일이 있고 `[[링크]]`가 1개 이상 | 파일은 있는데 `[[링크]]`가 0개 | 파일이 없음 |
| `log.md` | 파일이 있고 `##`로 시작하는 덩어리가 1개 이상 | 파일은 있는데 덩어리가 0개 | 파일이 없음 |
| `tags.md` | 파일이 있고 `분야/`·`종류/`·`활동/` 셋이 다 나옴 | 파일은 있는데 셋 중 빠진 게 있음 | 파일이 없음 |
| `장부.md` | 파일이 있고 다섯 칸짜리 표 머리가 있음 | 파일은 있는데 칸 수가 다름 | 파일이 없음 |

**숫자 줄**

- **창고 자료** · `raw/` 아래 하위 폴더까지 전부, 위 「빼고 세는 것」 적용
- **페이지** · `wiki/` 아래 `.md` 중 뼈대 넷과 `_`로 시작하는 것 제외
- **목차 등재율** · `index.md`의 `[[링크]]` 집합 ∩ 실제 페이지 이름 집합 / 페이지 수. 목차에만 있고 파일이 없는 줄은 이 분수에 안 넣고 한 줄 설명에 따로 적어요(예 · "목차에만 있고 파일이 없는 줄이 2개 있어요")
- **출처가 적힌 페이지** · 본문에 `## 출처`(또는 `## 원본`·`## Source`) 제목이 있고 그 아래에 **진짜 경로가 한 줄이라도** 있는 페이지 수 / 페이지 수. `- (확인 안 됨)`만 있는 페이지는 세지 않아요. 여기서 세는 건 「어디서 왔는지 아는 페이지」예요. **SKILL.md 8절 ⑤(`## 출처`가 없거나 「(확인 안 됨)」만 적힌 페이지)와 뒤집으면 같은 문장이에요.** 두 곳이 다르게 세면 같은 폴더를 놓고 점검은 「문제 0」, 안내 페이지는 「5/7」이라고 말하게 돼요
- **맨 위 머리가 있는 페이지** · 첫 줄이 `---`이고 닫는 `---`이 있는 페이지 수 / 페이지 수. `type`·`tags`까지 다 맞는지는 여기서 안 봐요. 있나 없나만요

**원본이 바뀐 흔적** · 아래 넷 중 하나라도 걸리면 `있음`이고, 걸린 파일 이름을 한 줄 설명에 최대 3개까지 적어요.

1. `raw/` 안에 `.md`나 `.txt`가 있는데 **이름이 같고 확장자만 다른 원본**이 옆에 있어요(`운영회의_0901.docx`와 `운영회의_0901.md`)
2. 이름 끝에 `_변환`·`_추출`·`_text`·`_ocr` 같은 꼬리표가 붙어 있어요
3. `raw/` 안에 `converted/`·`txt/`·`추출/` 같은 폴더가 있어요
4. `raw/` 안 파일 이름이 `page1.md`·`page2.md`처럼 번호만으로 이어져요

**세어만 보고 절대 지우지 않아요.** 진짜 변환본인지 원래 그런 원본인지는 사람이 알아요.

**연결된 소스** · `raw/_수집상태.json`을 읽어서 `sources`의 종류(메일·카톡)와 마지막 수집 날짜만 적어요. 파일이 없으면 `없음`이에요. **메일 주소는 표에 안 써요.** 「메일 한 곳 · 카톡 방 3개」처럼만요.

**밤 자동화** · `.inbox/야간수집.cmd`가 있으면 `있음`, 없으면 `없음`이에요. 있으면 `.inbox/collect.log` 마지막 줄의 날짜를 한 줄 설명에 적어요. **예약 작업이 진짜 등록됐는지는 진단에서 안 봐요.** 파일만 봐요. 진단은 읽기만 하는 단계라 명령을 돌리지 않아요.

### 2.5 진단에서 안 하는 것

- 페이지 내용을 읽고 사실을 대조하지 않아요. 그건 점검(8절)의 ⑥⑦이에요
- `raw/` 파일을 열지 않아요. 이름과 개수만 봐요
- 아무것도 안 고쳐요. 백업도 아직 안 해요

## 3. 계획 문구

### 3.1 진단 결과가 문장을 정해요

**계획은 진단표에서 기계적으로 나와요.** 지어내지 않아요. 아래 표에서 걸린 줄만 골라 번호를 매겨 보여드려요.

| 진단에서 이러면 | 이 문장을 써요 |
|---|---|
| 장부 없음 | 장부를 새로 만들고 창고 **N건**을 한 줄씩 적을게요. 이미 페이지가 된 것은 「올림」으로, 짝을 못 찾은 것은 「대기」로요 |
| 장부 다름(칸 수가 다름) | 지금 장부는 그대로 두고 옆에 우리 칸 다섯 개짜리 표를 새로 만들게요. 적혀 있던 줄은 옮겨 담을게요 |
| 서랍 없음 | 서랍 목록을 13개로 깔게요. 「무슨 일인가」 세 줄은 지금 페이지 주제에 맞춰 맞출게요 |
| 서랍 다름 | 지금 서랍은 그대로 두고, 빠진 묶음만 더할게요 |
| 목차 없음 | 목차를 만들고 페이지 **N장**을 한 줄씩 올릴게요 |
| 목차 미등재 N장 | 목차에 빠진 **N장**을 한 줄씩 더할게요. 이미 있는 줄은 손대지 않아요 |
| 목차에만 있고 파일이 없는 줄 N개 | 그 **N줄**은 지우지 않고 목록으로 보여드릴게요. 지울지 새로 만들지는 나중에 정하시면 돼요 |
| 기록 없음 | 기록 파일을 만들고 오늘 한 줄부터 시작할게요. **예전 회차는 지어내지 않아요** |
| 맨 위 머리 없음 N장 | 페이지 **N장** 맨 위에 종류·서랍·날짜 몇 줄을 더할게요. **본문은 한 글자도 안 건드려요** |
| 출처 없음 N장 | 출처는 제가 만들어 붙이지 않아요. **장부에서 짝이 잡히는 것만** 적고, 나머지는 「(확인 안 됨)」으로 둘게요 |
| 규칙 파일 다름 | `CLAUDE.md` 맨 아래에 우리 규칙 절을 **더할게요**. 지금 적혀 있는 건 그대로 둬요 |
| 규칙 파일 없음 | 규칙 파일을 새로 깔게요 |
| 원본이 바뀐 흔적 있음 | **고치지 않아요.** 목록만 보여드릴게요. 중복으로 볼지는 다음에 자료 넣을 때 정하면 돼요 |
| 아무것도 안 걸림 | 고칠 게 없어요. 안내 페이지만 다시 채워 드릴게요 |

**걸리지 않은 줄은 계획에 안 써요.** 대신 표 아래에 한 줄로 모아서 알려드려요 · "목차는 7장이 다 올라가 있어서 고칠 게 없어요."

**연결과 자동화는 계획에 번호를 붙이지 않아요.** 이번에 안 하는 일이라서요. 대신 계획 목록 **아래**에 한 줄 알림으로만 적어요 · "카톡·메일 연결과 밤 자동화는 이번에 안 해요. 나중에 「메일 연결해줘」라고 하시면 돼요." 번호를 붙이면 확인 질문 ③(몇 개 빼고)에서 **안 할 일을 빼겠다고 고르게** 돼요.

### 3.2 절대 하지 않는 것 다섯 가지

계획 문구 바로 아래에 **이 다섯 줄을 그대로** 붙여요. 줄이거나 바꾸지 않아요. 수강생이 제일 무서워하는 게 「내가 만든 게 없어지는 것」이에요.

```
이건 안 해요.

1. **이미 있는 페이지를 지우지 않아요.** 한 장도요
2. **페이지 본문을 고치지 않아요.** 맨 위 머리 몇 줄과 맨 아래 「## 출처」 절만 더해요. 이미 적혀 있는 줄은 한 글자도 안 건드려요
3. **창고(`raw/`)를 건드리지 않아요.** 이름도 내용도 자리도 그대로예요
4. **`CLAUDE.md`를 덮어쓰지 않아요.** 맨 아래에 절 하나를 더해요
5. **파일 이름을 바꾸지 않아요.** `index.md`를 `목차.md`로 바꾸거나 하지 않아요
```

2번의 예외 둘(맨 위 머리, 맨 아래 출처)을 **문장 안에 같이** 적는 게 중요해요. 「본문 불변」이라고만 쓰고 나중에 출처 절을 더하면 약속을 어긴 게 돼요.

### 3.3 백업

**계획을 설명할 때 1번으로 적고, 실행할 때 제일 먼저 해요.**

- 자리 · **위키 폴더 바깥, 형제 자리**예요. 위키 폴더 안에 두면 점검이 백업 사본을 진짜 페이지로 세요
- 이름 · `{위키폴더이름}_백업_{YYYY-MM-DD}` (예 · `내위키_백업_2026-09-19`)
- 같은 날 두 번 하면 뒤에 `_2`·`_3`을 붙여요. **덮어쓰지 않아요.** 어제 백업이 오늘 실수를 덮으면 되돌릴 게 없어져요
- 통째로 복사해요. `raw/`도 같이요

**창고가 아주 클 때만 예외예요.** `raw/`가 **파일 1,000개를 넘거나 2GB를 넘으면** `raw/`를 빼고 `wiki/`와 규칙 파일만 복사하고, 그렇게 했다고 한 줄 말해요 · "창고가 커서 `raw/`는 빼고 복사했어요. 창고는 어차피 안 고치니까 괜찮아요."

복사가 실패하면(자리가 없거나 권한이 없으면) **거기서 멈춰요.** 백업 없이 실행하지 않아요. 한 줄로 알려드리고 어디에 복사할지 여쭤봐요.

### 3.4 확인 질문 · 딱 한 번

계획 문구 다음에 **한 번만** 여쭤봐요. 항목마다 묻지 않아요.

```
이대로 할까요?

① 네, 그대로 해 주세요 (추천)
② 백업만 하고 멈춰 주세요
③ 몇 가지는 빼고 할게요 (계획 번호로 알려 주세요)
```

- 계획 항목에 **번호가 있어야** ③이 돼요. 그래서 계획은 번호 목록으로 써요
- **답을 기다려요.** 이 스킬은 평소에 올림·버림을 묻지 않고 정하는데, **여기만 예외예요.** 이유는 **남이 손으로 만들어 둔 폴더**라서예요. 위키를 새로 만들 때는 잃을 게 없지만 여기는 있어요. 이미 쌓아 둔 페이지가 사용자에게는 몇 시간짜리 숙제예요
- ②를 고르시면 백업만 하고 "백업은 `...`에 뒀어요. 준비되시면 「계속해줘」라고 하세요."로 끝내요
- 진단표가 「고칠 게 없어요」로 나오면 **이 질문을 아예 안 해요.** 안내 페이지만 다시 채우고 보고해요

---

## 4. 실행 순서 · 비파괴

확인을 받은 다음이에요. **순서를 바꾸지 않아요.** 뒤 단계가 앞 단계 결과를 쓰거든요.

### 단계 1 · 백업

3.3 그대로예요. 실패하면 여기서 멈춰요.

### 단계 2 · 뼈대 파일 중 없는 것만 만들기

`templates/`의 다섯 개 중 **진단에서 `없음`으로 나온 것만** 복사해요. `있음`·`다름`은 손대지 않아요.

- `CLAUDE.md`(위키 루트) · `index.md`·`log.md`·`tags.md`·`장부.md`(`wiki/` 안)
- `tags.md`를 **이번에 새로 깔았을 때만** 「무슨 일인가」 세 줄을 지금 페이지 주제에 맞춰 갈아끼워요. 주제는 **목차의 섹션 이름과 페이지 제목**에서 뽑아요. 파일을 열어 읽지 않아요
- `tags.md`가 이미 있었으면 **세 줄을 바꾸지 않아요.** 기존 페이지에 붙은 태그까지 같이 고쳐야 해서 사용자가 정할 일이에요(SKILL.md 10절과 같은 규칙)
- `log.md`를 새로 만들었으면 **오늘 덩어리 하나만** 써요. 예전 회차를 지어내지 않아요

실패하면 · 그 파일만 건너뛰고 나머지를 계속해요. 마지막 보고에 "이 파일은 못 만들었어요"를 적어요.

### 단계 3 · 페이지 맨 위 채우기

`맨 위 머리가 있는 페이지`가 전부가 아닐 때만 해요.

- 첫 줄에 `---`가 **없는** 페이지만 대상이에요. 있으면 **빠진 키만** 더하고 있는 값은 안 고쳐요
- 넣는 줄 · `type` · `tags`(`분야/` 하나, `종류/` 하나, `활동/` 하나) · `created`
- `type` 정하는 법 · ① 목차에서 그 페이지가 들어 있는 섹션 ② 페이지 제목 ③ 첫 문단. 셋으로도 애매하면 `기록`이에요. **본문을 읽어서 추측하지 않아요**
- **손으로 만든 목차는 섹션 이름이 우리 여섯 종류와 달라요**(「계획·예산」·「거래처·견적」·「콘텐츠」 같은 것). 그럴 때는 ①을 건너뛰고 **제목의 끝 낱말**을 봐요 · 회의·미팅·간담회 → `회의` · 계획·정산·견적·내역·보고·요청·시안 → `기록` · 사람 이름만 → `사람` · 회사·팀·기관 이름만 → `조직` · 여러 달 이어지는 일 이름 → `프로젝트` · 뜻풀이나 방법 → `개념`
- **한 종류에 다 몰리면 안 돼요.** 전부 `기록`이 되면 `종류/` 서랍이 한 칸으로 쏠려서 태그가 쓸모없어져요. 세 종류 아래로 몰렸으면 제목을 한 번 더 훑어봐요
- `created` · 오늘 날짜예요. 페이지가 실제로 만들어진 날이 아니에요. 지어내지 않아요
- `started`·`ended`·`checked`·`aliases` · **비워 둬요.** 본문에 날짜가 있어도 그게 시작일인지 아닌지는 몰라요
- **본문은 한 글자도 안 건드려요.** `---` 블록을 맨 앞에 끼우고 그 아래에 원래 내용이 그대로 이어져요
- 제목 줄(`# ...`)이 본문 첫 줄이면 그대로 둬요. 맨 위 머리가 그 위로 가요

실패하면 · 그 페이지만 건너뛰어요. 몇 장이 안 됐는지 보고에 적어요.

### 단계 4 · 목차에 빠진 줄 더하기

- 미등재 페이지만 한 줄씩 더해요. **이미 있는 줄은 순서도 문구도 안 고쳐요**
- **기존 목차의 줄 모양을 따라가요.** 지금 목차가 `- [[페이지]] · 설명`이면 그 모양으로 써요. 우리 템플릿 모양(`- [[페이지]]: 설명`)으로 통일하지 않아요. 통일하려고 기존 줄을 건드리면 2번 약속을 어겨요
- 섹션 · 기존 섹션 중에 맞는 데가 있으면 거기로요. 없으면 템플릿 여섯 섹션을 **아래에 이어 붙여요.** 기존 섹션을 지우거나 이름을 바꾸지 않아요
- 설명 한 줄 · 페이지 제목과 첫 문단에서 뽑아요. 못 뽑으면 제목을 그대로 써요

### 단계 5 · 장부 채우기 · 출처 붙이기

이 단계가 제일 중요해요. **장부 초기화와 출처 보강이 한 단계예요.** 둘 다 「어느 파일이 어느 페이지가 됐나」라는 같은 질문이거든요.

0. **먼저 장부를 봐요.** 다섯 칸짜리 표가 이미 있으면 **없는 줄만** 더해요. 이 단계도 다른 단계와 똑같이 「없을 때만 한다」예요
1. `raw/` 전수를 훑어요(하위 폴더 포함, `_`로 시작하는 것 제외). **전부 한 줄씩** 장부에 적어요. 한 건도 빼지 않아요. **다만 그 상대 경로가 장부에 이미 있으면 그 줄은 건너뛰어요.** 안 그러면 두 번째 실행에서 장부가 두 배가 돼요
2. 원본 파일 칸에는 **`raw/`부터의 상대 경로**를 적어요
3. 파일마다 페이지와 짝을 맞춰 봐요. 짝을 찾는 순서는 이래요
   - ① 어느 페이지의 `## 출처`에 그 경로가 이미 적혀 있으면 → **올림** (확실)
   - ② 파일 이름의 핵심 낱말이 페이지 제목에 그대로 나오면 → **올림** (예 · `운영회의_0901.docx` → `운영회의 2026-09-01`). **핵심 낱말**은 파일 이름에서 확장자·날짜·`최종`·`수정`·`사본`·`진짜`·`v2` 같은 꼬리표를 뺀 나머지예요
   - **견줄 때는 양쪽에서 공백과 밑줄을 빼고 봐요.** 한글 파일 이름에는 공백이 없어서 그냥 견주면 맞는 짝도 안 걸려요(`9월_운영준비비` ↔ `9월 운영 준비비`)
   - **긴 것부터 봐요** · ㉠ 꼬리표를 뺀 이름 **전체** ㉡ 그 안의 낱말을 **긴 것부터** 하나씩. 먼저 걸리는 데서 멈춰요. 짧은 낱말부터 보면 아무 데나 걸려요
   - **두 글자 이하인 낱말과 `9월`·`8월` 같은 달 이름만으로는 짝을 잡지 않아요.** 너무 흔해서 세 장에 한꺼번에 걸려요
   - **두 장 이상에 걸리면 거기서 멈추지 말고 ③으로 내려가요.** ③까지 가서도 한 장으로 안 좁혀지면 `대기`예요. 엉뚱한 페이지에 출처가 붙는 게 짝을 못 찾는 것보다 나빠요
   - ③ 파일 이름의 핵심 낱말이 페이지 본문에 나오고 다른 페이지에는 안 나오면 → **올림**
   - **③은 ㉠(꼬리표를 뺀 이름 전체)으로만 봐요.** 낱말 하나가 본문에 스쳐 지나간 건 짝이 아니에요. 「회의자료에 8월 마감이 섞여 있다」는 문장은 그 페이지가 그 회의자료에서 나왔다는 뜻이 아니거든요
   - **애매하면 `대기`로 두면 돼요.** 손해가 없어요. 나중에 「밀린 거 처리해줘」가 그 파일을 열어 읽고 제대로 붙여요
   - ④ 어디에도 안 잡히면 → **대기**
4. 상태는 둘만 써요 · `올림`·`대기`. **`버림`과 `보류`는 여기서 안 써요.** 아직 파일을 안 읽었으니 버릴 근거가 없어요
5. 이유 칸 · 올림이면 `기존 페이지와 짝이 잡힘`, 대기면 `기존 위키에 올린 흔적 없음`
6. 만든 페이지 칸 · 올림이면 대괄호 두 개로 감싼 페이지 이름이에요
7. **같은 페이지에 파일 여럿이 붙어도 그대로 둬요.** 같은 문서의 여러 버전을 한 페이지에 합쳐 놓은 위키가 많아요. 그걸 「중복이니 하나는 버림」으로 바꾸면 사용자가 이미 내린 판단을 뒤집는 거예요
8. **올림으로 잡힌 파일만** 그 페이지 `## 출처`에 경로를 더해요. `## 출처` 절이 없으면 맨 아래에 새로 만들고, **이미 있으면 그 절 안에 줄만 더해요.** 이미 적힌 경로는 다시 안 적어요
9. 짝을 못 찾은 페이지는 `## 출처` 절을 만들고 `- (확인 안 됨)` 한 줄만 넣어요. **`## 출처` 절이 이미 있으면 새로 만들지 않아요.** 절이 둘이 되면 점검이 그 페이지를 두 번 세요. **파일 이름을 추측해서 적지 않아요**

끝났으면 확인해요 · **장부 행 수 = `raw/` 파일 수**(`_`로 시작하는 것 제외). 안 맞으면 보고에 적고 왜 그런지 한 줄 남겨요.

### 단계 6 · `CLAUDE.md`에 규칙 절 더하기

파일이 **있는데 우리 규칙 절이 없을 때**예요. 없으면 단계 2에서 이미 템플릿을 깔았어요.

- **맨 아래에 절 하나를 붙여요.** 위 내용은 한 글자도 안 고쳐요
- 제목은 고정이에요 · `## 이 위키의 규칙 (llm-wiki-factory)`
- 안에 넣는 것 · 약속 네 가지 · 자료 넣기 순서 · 판정 셋 · 페이지 형식 · 목차와 서랍 · 안 하는 것. `templates/CLAUDE.md`의 해당 절들을 그대로 옮겨요. **새로 쓰지 않아요**
- 맨 앞에 한 줄 · "위에 적힌 규칙과 어긋나면 **위에 적힌 게 먼저예요.** 이 절은 나중에 붙인 거예요." 사용자가 직접 쓴 규칙을 우리가 이기면 안 돼요
- 맨 위 현황 줄(`현황: 페이지 N장 · 자료 N건 · 마지막 정리 ...`)은 **파일 맨 앞에 그 줄이 이미 있을 때만** 갱신해요. 없으면 만들지 않아요

### 단계 7 · 안내 페이지 만들기

`references/안내페이지.md` 그대로예요. **다 채우고 나서** 만들어요. 숫자가 방금 바뀌었거든요.

### 단계 8 · 보고 다섯 줄

**딱 다섯 줄이에요.** 길어지면 뭐가 바뀌었는지가 안 보여요.
