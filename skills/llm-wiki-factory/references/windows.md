# Windows·한글 환경에서 조심할 것

이 위키를 다룰 때 실제로 밟는 것만 모았어요.
한글 파일 문제가 자주 나면 `korean-safe-windows` 스킬을 같이 설치하시면 더 자세해요.

## 1. 한글 파일 이름 (제일 자주 걸려요)

같은 이름처럼 보여도 **속이 다르게 저장돼 있을 수 있어요**(자모가 분리된 형태로 저장된 경우).

- **파일 이름을 문서에 적힌 이름과 맞춰볼 때는 언제나 양쪽 다 같은 형태로 바꿔서 비교해요**(이 형태를 NFC라고 불러요). 어느 한쪽만 바꾸면 안 돼요.
- 가장 자주 도는 대조가 **장부 표의 원본 파일 칸 대 `raw/`의 실제 파일 이름**이에요. 여기서 어긋나면 이미 처리한 파일을 또 새 자료로 잡아서 같은 페이지가 두 장 생겨요.
- `[[페이지이름]]` 링크를 실제 파일과 맞춰볼 때도 같아요. 목차 대조도, 깨진 링크 세기도 마찬가지예요.
- 파일을 열거나 다룰 때는 **폴더를 열거해서 얻은 실제 경로**를 써요.
- 표나 문서에 적힌 글자로 경로를 조립하지 않아요.
- 이름에 특정 글자가 들어 있는지만 보고 "찾았다"고 하지 않아요.
- **기존 파일 이름을 일괄로 바꾸지 않아요.** 원본 창고는 그대로 둬요.
- **새로 만드는 위키 페이지에 한글 이름을 쓰는 건 괜찮아요.**

## 2. 저장 방식 · UTF-8과 BOM

- 위키의 `.md` 파일은 **BOM 없는 UTF-8**로 써요.
- **AI의 파일 쓰기 도구로 직접 써요.** Windows PowerShell 5.1의 `>`와 `Out-File`은 UTF-16으로, `Set-Content`는 CP949로 저장할 수 있어요.
- 읽을 때도 PowerShell 5.1의 `Get-Content`는 BOM 없는 UTF-8을 CP949로 읽어서 깨져 보일 수 있어요.
- **BOM은 엑셀에서 열 CSV에만** 써요(`utf-8-sig`). 마크다운에는 안 넣어요.

## 3. 화면에 보이는 것과 파일 내용은 달라요

- 한글이 깨져 보이거나 빈칸으로 나와도 파일이 망가졌다고 단정하지 않아요.
- 결과를 UTF-8 파일로 저장한 뒤 **파일 읽기 도구로 다시 확인**해요.
- 깨진 글자를 버리고(`errors='ignore'`) "됐다"고 하지 않아요.

## 4. 경로와 파일 이름

- **항상 큰따옴표**로 감싸요. 예: `"C:/Users/김수강/Documents/내 위키"`
- 한글 사용자 이름(`C:\Users\홍길동`)을 봤다는 이유로 계정명이나 폴더 이름을 바꾸지 않아요.
- 폴더 이름을 특정 글자로 고정하지 않아요. 다운로드 중복 `(1)`, OneDrive 경로도 그대로 다뤄요.
- Git Bash를 쓰더라도 PowerShell 문법은 `powershell.exe`나 `pwsh`에 명시적으로 넘겨요. 경로는 `-LiteralPath`로, 실행 파일은 `&`로 불러요.

**새 파일 이름에 못 쓰는 글자가 아홉 개 있어요.** `\ / : * ? " < > |` 예요. Windows가 저장을 거부해요.
페이지 이름과 「물어본 답」 제목은 사용자가 한 말에서 나오니까 여기 자주 걸려요. 이렇게 바꿔 저장해요.

| 사용자가 한 말 | 저장할 이름 |
|---|---|
| `A/B 테스트 결과는?` | `A-B 테스트 결과` |
| `견적: 모아결 vs 다른 곳` | `견적 비교 모아결 대 다른 곳` |
| `2026/09 정산` | `2026-09 정산` |

원래 제목은 버리지 말고 **본문 첫 줄이나 `aliases:`에 적어요.**

두 가지 더 있어요.

- **예약된 이름은 파일 이름으로 못 써요.** `CON` `PRN` `AUX` `NUL` `COM1`~`COM9` `LPT1`~`LPT9`. 확장자를 붙여도 안 돼요(`CON.md`도 안 됨). 뒤에 글자를 붙이면 괜찮아요(`CON 회의록.md`).
- **전체 경로가 260자를 넘으면 저장이 실패해요.** 위키를 `C:\Users\김수강\Documents\내위키`처럼 짧은 곳에 두고, 페이지 이름을 40자 안쪽으로 지으면 안 걸려요. 이름 끝에 `.`이나 공백을 두지도 않아요.

## 5. 동기화 폴더 (OneDrive·구글드라이브·Dropbox)

- 위키는 **동기화 폴더 밖**에 두는 걸 권해요.
- 이미 안에 있으면 `index (1).md` 같은 충돌 사본이 생길 수 있어요. 점검할 때 이런 파일이 있는지 같이 봐요.
- 충돌 사본을 진짜 페이지로 세지 않아요.

## 6. 유닉스 명령은 안내하지 않아요

- 카파시 원안에는 `grep "^## \[" log.md | tail -5` 같은 예시가 있지만 **PowerShell에는 `grep`도 `tail`도 없어요.**
- 같은 일을 말로 시키면 돼요. "최근 5회 기록 보여줘."

## 7. `@`로 파일을 지정하는 게 안 될 때

- `@`가 안 떠도 괜찮아요. 이 스킬은 **폴더를 통째로 읽는 흐름**이라 파일을 지목할 필요가 없어요.
- "raw 폴더에 넣고 '위키에 넣어줘'라고만 하세요."

## 8. Claude 앱 재시작

- 창의 X를 눌러도 트레이(작업표시줄 숨은 아이콘)에 남아 있어요.
- **숨은 아이콘 → 우클릭 → 종료** 후 다시 열어야 설정이 반영돼요.

## 9. 되돌리기

- 이 스킬은 깃을 쓰지 않아요. 되돌리기는 **위키 폴더를 바깥에 통째로 복사**해 두는 걸로 해요.
- 점검이나 대량 정리를 하기 **전에** 한 번 복사해요.

**탐색기에서 하는 게 제일 쉬워요.** 위키 폴더를 한 번 누르고 `Ctrl+C`, 한 단계 위 폴더에서 `Ctrl+V`.
생긴 폴더 이름을 `내위키_백업_2026-09-19`처럼 날짜를 붙여 바꿔 주세요. 그게 전부예요.

명령으로 하고 싶으시면 이렇게예요.

Windows PowerShell
```powershell
Copy-Item -LiteralPath "$HOME\Documents\내위키" -Destination "$HOME\Documents\내위키_백업_2026-09-19" -Recurse
```

macOS·Linux
```bash
cp -R ~/Documents/내위키 ~/Documents/내위키_백업_2026-09-19
```

## 10. 원본 파일이 안 읽힐 때

순서는 SKILL.md 4절에 있고, **글자를 뽑는 코드는 `references/원본읽기.md`에 있어요.** Word·PPT·엑셀·메일 전부 파이썬에 처음부터 들어 있는 기능으로 풀려요. **설치할 건 하나도 없어요.**

## 11. 깔아야 할 건 없어요

이 스킬에는 실행할 스크립트도, 설치할 프로그램도 없어요.
10번에 나오는 건 파이썬에 처음부터 들어 있는 기능이라 따로 받을 게 없어요.
깃도, 인터넷 연결도 필요하지 않아요.
